# Интеграционные рекомендации (Assets/Code)

Этот документ фиксирует правила и выводы по интеграции и отладке внешних SDK и плагинов.

## Отладка сторонних SDK

- Если сторонний SDK или плагин работает некорректно, а в наших логах нет явной причины, сначала проверять, есть ли у вендора device/debug/verbose logs, и собирать именно их до любых изменений кода или настроек.
- На Android предпочитать `adb logcat`, а не только Lunar/Unity console, потому что ошибки native SDK могут появляться только в системных логах.
- Если у вендора есть инструкция уровня `Check your integration`, `Enable debug logs` или `Verbose logging`, проходить её в самом начале расследования.
- Тратить время на изменения кода, обновление SDK или гипотезы про backend/setup только после просмотра vendor-specific debug logs.

## Колбэки SDK и потоки

- Колбэки рекламных, платёжных и аналитических SDK могут приходить не с главного потока. Любые обращения к Unity API из таких колбэков переводить на Unity main thread через существующую инфраструктуру проекта.
- Не вызывать `FindAnyObjectByType`, `FindObjectOfType` и другие runtime-поиски из SDK-колбэков. Зависимости прокидывать заранее через DI, события или явные ссылки.

## Уроки DevToDev

- В кейсе с DevToDev Payments реальная причина проблемы не была видна, пока не включили `DTDLogLevel.Debug`.
- Без vendor debug logs ситуация выглядела как backend- или UI-проблема.
- После включения debug logs стало ясно, что `DTDPurchases.StartAutoTracking()` падал слишком рано с `null reference`.

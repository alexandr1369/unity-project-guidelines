# Общие правила Unity-проектов

`unity-project-guidelines` — один навык для Codex и Claude Code. Главный файл —
[SKILL.md](SKILL.md), подробные правила остаются в отдельных MD рядом с ним.
Это принятые командой конвенции, а не универсальные требования Unity.

## Как устроено подключение

1. В корне каждого подключённого проекта находятся `AGENTS.md` и `CLAUDE.md`:
   требование применять навык и особенности проекта. Содержимое пары одинаковое.
2. В личном каталоге навыков каждого агента находится папка или ссылка с именем
   `unity-project-guidelines`. Внутри неё агент находит `SKILL.md`.
3. `SKILL.md` направляет к профильным документам и объясняет, куда добавлять правила.

Локально исходник можно держать в любом постоянном каталоге, а обоим агентам дать
ссылку на него. Название и расположение исходной папки не влияют на пути внутри навыка.
Общие `AGENTS.md` / `CLAUDE.md` над репозиториями не нужны. На поиск Codex выше корня
репозитория и на автоматическое разворачивание им `@`-импортов не рассчитываем.
Настройка `project_doc_fallback_filenames` для этой схемы не требуется.

Навык доступен для автоматического выбора по описанию и для явного вызова. Требование
применять его задаётся в инструкциях проекта; установка сама по себе не гарантирует
его использования во всех задачах или безошибочного исполнения правил.

## Установка другому человеку

Не нужно воспроизводить расположение папок автора. Достаточно одного клона навыка
и подключения нужных проектов.

### Самый простой вариант

Клонируй [репозиторий навыка](https://github.com/alexandr1369/unity-project-guidelines)
в постоянное место (`git clone https://github.com/alexandr1369/unity-project-guidelines.git`).
Передай своему Codex или Claude Code путь к клону и такую задачу:

> Установи навык unity-project-guidelines из этой папки по её README.md.
> Подключи его к моему Codex и Claude Code, если они установлены, ссылками на один оригинал.
> В выбранных мной Unity-проектах добавь требование использовать навык в корневые
> AGENTS.md и CLAUDE.md, сохрани существующие инструкции. Проверь обнаружение и ссылки.
> Покажи мне командные конвенции, которые потребуется адаптировать под мои проекты.

Также укажи пути своих проектов. Не передавай ассистенту только `SKILL.md`: нужны
все профильные MD и каталог `scripts`, если используешь приложенный Git-хук.
Обновляй клон через `git pull`.

### Вручную на macOS / Linux

Помести клонированную папку, например, в `~/agent-skills/unity-project-guidelines`.
Если она лежит в другом месте, замени только значение `unity_skill_source`:

```sh
unity_skill_source="$HOME/agent-skills/unity-project-guidelines"
mkdir -p "$HOME/.agents/skills" "$HOME/.claude/skills"
ln -s "$unity_skill_source" "$HOME/.agents/skills/unity-project-guidelines"
ln -s "$unity_skill_source" "$HOME/.claude/skills/unity-project-guidelines"
```

Если установлен только один агент, создай только его ссылку. Не перезаписывай уже
существующий навык: сначала проверь, куда он подключён. Исходную папку после подключения
не перемещай; если переместил — обнови ссылки. Не создавай дополнительную копию в
`~/.codex/skills`, если навык уже обнаруживается через `~/.agents/skills`.

### Вручную на Windows

Помести клонированную папку в постоянное место, например `%USERPROFILE%\agent-skills\unity-project-guidelines`.
В PowerShell создай каталоги подключения и junction-ссылки на один оригинал:

```powershell
$unitySkillSource = Join-Path $env:USERPROFILE 'agent-skills\unity-project-guidelines'
$codexSkills = Join-Path $env:USERPROFILE '.agents\skills'
$claudeSkills = Join-Path $env:USERPROFILE '.claude\skills'
New-Item -ItemType Directory -Force -Path $codexSkills, $claudeSkills | Out-Null
New-Item -ItemType Junction -Path (Join-Path $codexSkills 'unity-project-guidelines') -Target $unitySkillSource
New-Item -ItemType Junction -Path (Join-Path $claudeSkills 'unity-project-guidelines') -Target $unitySkillSource
```

Это вариант для локального диска. Для Codex/Claude в WSL устанавливай навык внутри WSL
по инструкции Linux: Windows-профиль и домашняя папка WSL — разные места подключения.

## Подключение каждого проекта

В корневые `AGENTS.md` и `CLAUDE.md` добавь одинаковый блок ниже, сохранив существующие
особенности проекта. Если инструкции двух агентов уже различаются, сначала согласуй их
в единый текст; не затирай один файл копией другого вслепую.

```md
## Общие Unity-правила

Перед работой в этом проекте обязательно используй навык `unity-project-guidelines`:
прочитай его `SKILL.md`, базовые и подходящие к задаче профильные документы.
Codex: `~/.agents/skills/unity-project-guidelines/SKILL.md`.
Claude Code: `~/.claude/skills/unity-project-guidelines/SKILL.md`.
`~` означает домашнюю папку пользователя; ссылки внутри навыка разрешаются от его папки.
Если навык не обнаружен в списке, открой указанный файл напрямую. Если файл недоступен,
сообщи о проблеме подключения до изменений проекта; не считай общие правила прочитанными.
Особенности ниже дополняют общие правила. Изменяй `AGENTS.md` и `CLAUDE.md` вместе,
сохраняя их побайтовое равенство.
```

Для переносимых репозиториев используй этот блок без абсолютных путей автора и без
`../_guidelines`. Он работает и в отдельном клоне, и в Git worktree после установки навыка.
В новом проекте ниже блока укажи пути к исходникам, наличие Entitas, особенности 2D/3D,
используемые плагины и свои договорённости по Git. Не копируй особенности одного проекта
в другой.

### Командные конвенции и Git-хук

Перед первым применением ознакомься с правилами: здесь приняты конкретные архитектура,
стиль C#, рабочий процесс Git и меню `Rokot Games`. Если у твоей команды другие
договорённости, адаптируй свою копию в профильных MD. Префикс веток и особенности remote
задавай в инструкциях конкретного проекта.

Существующий `scripts/git-hooks/pre-commit` проверяет побайтовое равенство пары
`AGENTS.md` / `CLAUDE.md`. Для установки самого навыка этот хук не требуется. Если хочешь
подключить его в новом проекте, скопируй файл из навыка в тот же относительный путь проекта,
сохрани право исполнения и настрой `git config core.hooksPath scripts/git-hooks`.
Если в проекте уже есть хуки, объедини проверки, не перезаписывай их. Настройка
`core.hooksPath` локальная: её повторяют в каждом клоне.

## Проверка подключения

1. Открой новую сессию агента в подключённом проекте. Если навык не появился, перезапусти агент.
2. В Codex выбери `unity-project-guidelines` в списке навыков; в CLI доступен
   `$unity-project-guidelines`. В Claude Code используй `/unity-project-guidelines`.
3. Попроси: «Ничего не меняй. Покажи путь к SKILL.md, назови базовые документы,
   документ для async и применяется ли Entitas к этому проекту».
4. Проверь: базовые — `CODE_STYLE.md` и `GIT_WORKFLOW.md`, async — `STATE_FLOW_AND_ASYNC.md`;
   Entitas определяется особенностями проекта. Убедись, что агент действительно прочитал файлы.

## Изменения и экспорт

Куда записывать правила, определяет раздел «Куда записывать новые правила» в [SKILL.md](SKILL.md).
Просьба «добавь это в наши Unity-правила» должна менять соответствующий MD этого навыка.
При подключении ссылками изменения сразу доступны обоим агентам; перезапуск помогает,
если текущая сессия продолжает использовать ранее прочитанный текст.

Для нового экспорта упакуй актуальные корневые `*.md` (кроме локального `TASKS.md`) и
`scripts/` в ZIP с единственной верхней папкой `unity-project-guidelines`. Не включай
`.git`, `.DS_Store`, локальные задачи, архивы и файлы самих Unity-проектов. Передавай реальные
файлы исходника, а не ссылки из личных каталогов агентов. Экспорт — снимок: изменения
оригинала не обновят автоматически уже отправленную копию.

Если папка ведётся в Git, изменения оформляй в отдельной task-ветке по `GIT_WORKFLOW.md`.
При отсутствии remote ревью и merge выполняются локально после просмотра владельцем diff;
если remote появился — используй PR. Не добавляй личные настройки автора в общий навык.
